The panel exposes per-user activity stats (clients owned, scans run, patches, findings, audit-log entries), the user's last login, and their last 5 audit-log entries — all from a single aggregated API endpoint that hits the DB in a bounded number of batched round-trips.

  2169→### Files created
  2170→
  2171→#### 1. `src/app/api/admin/user-activity/route.ts` (~370 lines)
  2172→- `GET /api/admin/user-activity` — admin-only (uses `requireAdmin` + `enforceSessionRevocation` from `@/lib/auth`).
  2173→- Returns `{ users: UserActivitySummary[], totals: { users, activeToday, clients } }`.
  2174→- Per-user summary includes: id, email, name, role, approved, createdAt, lastLoginAt, lastLoginIp, `stats` (clients, scans, patches, findings, auditEntries), and `recentActivity` (last 5 audit entries — action/entity/timestamp only, never `details`).
  2175→- **Query strategy (avoids N+1):**
  2176→  1. Fetch all users (admins included).
  2177→  2. Batch-fetch the entity graph in parallel: Clients (id, ownerId), Codebases (id, clientId), Scans (id, codebaseId), Patches (id, codebaseId), Targets (id, clientId), Engagements (id, targetId), Findings (id, engagementId) — each with a generous row cap.
  2178→  3. Fetch the most recent N LoginHistory rows (across all users) ordered desc by timestamp — dedupe per userId in JS (PostgREST can't do `DISTINCT ON`).
  2179→  4. Fetch the most recent N AuditLog rows ordered desc — bucket per actor in JS to get both "last 5 per user" and the "active today" set in a single round-trip.
  2180→  5. Issue exact per-user AuditLog count queries in parallel — skipped if the global recent window hasn't been exhausted (in that case the bucketed tally is already exact).
  2181→- **"Active today"** = user has ≥1 audit-log entry today OR a login today (cross-tallied via the same `actorsActiveToday` set).
  2182→- Results sorted: active-today users first, then by client count desc, then by name.
  2183→- Defense-in-depth: the `recentActivity` payload returns only `action`, `entity`, `timestamp` — never the `details` JSON. The `auditLog()` helper itself already strips passwords/tokens, so this is a second layer.
