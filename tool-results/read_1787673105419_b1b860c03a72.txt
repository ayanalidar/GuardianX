    28→### What landed
    29→
    30→**AI Memory Vault** (`src/lib/memory-vault/` + `src/app/api/memory/`)
    31→
    32→- `src/lib/memory-vault/memory-store.ts` — Supabase-backed
    33→  `MemoryEntry` table accessor (proxied via `db.memoryEntry.*` in
    34→  `src/lib/db.ts`). `storeMemory`, `getMemories`, `searchMemories`,
    35→  `getRecentContext`. Content capped at 500 chars. Categories:
    36→  `scan_result | finding | patch | user_preference | conversation |
    37→  client_context | threat_intel` (the 5 required + 2 extras for
    38→  future scope).
    39→- `src/lib/memory-vault/memory-context.ts` — `buildContextForChat(userId)`
    40→  pulls the latest 5 scans / 10 findings / 8 patches / 5 prefs / 6
    41→  conversations and shapes them into a markdown block (## Recent
    42→  Activity / ## Active Threats / ## User Preferences / ## Recent
    43→  Conversation) that gets injected into the Guardian chat system
    44→  prompt. Open findings are surfaced as "Active Threats" via the
    45→  `status:open` tag, and drop off once a matching `status:patched`
    46→  memory is written.
    47→- `src/lib/memory-vault/memory-writer.ts` — fire-and-forget event
    48→  writers (`onScanComplete`, `onFindingFound`, `onPatchApproved`,
    49→  `onUserMessage`, `onAssistantReply`, `onUserPreference`) that
    50→  convert platform events into memories. Failures are swallowed
    51→  (logged) so a memory write never blocks the user-facing flow.
    52→- `src/app/api/memory/route.ts` — `GET /api/memory?category=&limit=`
    53→  and `POST /api/memory { category, title, content, tags? }`,
    54→  `requireAuth`-gated.
    55→- `src/app/api/memory/context/route.ts` — `GET /api/memory/context`
    56→  returns the built markdown string + char count (used by
    57→  `guardian-chat.tsx` to badge the header with vault size).
    58→- `src/app/api/memory/ingest/route.ts` — internal POST for the
    59→  sentinel-engine to record off-band events (scan_complete /
    60→  finding_found / patch_approved / user_preference) so the vault
    61→  stays current without the chat route having to be in the loop.
    62→- `supabase/migrations/0009_memory_vault.sql` — creates the
    63→  `MemoryEntry` table with indexes on `(userId, createdAt DESC)` and
    64→  `(userId, category, createdAt DESC)`, RLS disabled (the app uses
    65→  service_role). Mirrored in `prisma/schema.prisma` as the
    66→  `MemoryEntry` model.
    67→- `src/components/sentinel/guardian-chat.tsx` — header now badges a
    68→  `Brain` icon with the live vault size in chars; the actual context
    69→  is fetched server-side by `/api/guardian-chat/route.ts`, merged
    70→  into the system prompt as a `Memory vault (recent activity...)`
    71→  block with a fallback "(memory vault is empty — this may be a new
    72→  user)" string when fresh. After each turn the assistant reply
    73→  length is echoed back so the badge updates without a refetch.
    74→- `src/app/api/guardian-chat/route.ts` — `onUserMessage` is fired
    75→  before the LLM call, `onAssistantReply` after, so the next turn
    76→  already has the prior turn as context. Best-effort: a thrown
    77→  memory write is caught and warned, never blocks the reply.
    78→
    79→**AI Visualizer** (`src/components/sentinel/ai-visualizer/`)
    80→
    81→- `src/components/sentinel/ai-visualizer/circuit-board.tsx` —
    82→  canvas-based React port of the `board` face. Procedurally routes
    83→  traces across a grid (mulberry32 RNG, seed 7 so the board looks
    84→  identical every boot), places ~34 components (ICs / resistors /
    85→  caps) on top, and spawns data pulses that flow along the traces
    86→  lighting up components as they hit. A central chip "breathes" at
    87→  idle and amps up under load. Pulses spawn from chip pins outward,
    88→  ~62% biased to the chip side. Pulses use additive blending with a
    89→  cached radial-gradient glow sprite (the same `makeGlow` trick from
    90→  `core.js` `U.makeGlow`). rAF loop is paused when the canvas is
    91→  off-screen (IntersectionObserver) or the tab is hidden, and DPR is
    92→  capped at 1.5 — matches the perf rules in `core.js`. HUD: corner
    93→  brackets, GUARDIANX brand, status mode label, live clock, signal
    94→  indicator. `forcedState` prop lets callers pin a state without the
    95→  bus (used by the landing particle-bg variant).
    96→- `src/components/sentinel/ai-visualizer/signal-bus.tsx` — React
    97→  Context provider that owns the single source of truth for the
    98→  visualizer state. Connects to the sentinel-engine socket.io relay
    99→  (via `ENGINE_SOCKET_URL` + `engineSocketOptions()` from
   100→  `src/lib/sentinel/engine-socket.ts`) and listens for
   101→  `pipeline:event` payloads. Each event is mapped (by message regex
   102→  on stage/message/level) to one of five states:
   103→  `idle | scanning | analyzing | finding | patching`. States
   104→  auto-expire (scanning 30s, analyzing 20s, finding 4s, patching 6s)
   105→  so a missed "scan_complete" doesn't strand the board in `scanning`
   106→  forever. Keeps a 40-event ring buffer for the live feed. Also
   107→  exposes `push()` so local UI actions (e.g. "user approved a patch")
   108→  can drive the visualization without waiting for the engine to
   109→  echo them back. `useSignalBus()` returns a no-op shim when used
   110→  outside a provider, so leaf components (homepage particle bg)
   111→  don't crash without a provider.
   112→- `src/components/sentinel/ai-visualizer/neural-link.tsx` — bonus
   113→  port of the `neural` face (constellation of brain-region clusters
   114→  with traveling dots along bezier tendrils). Same state mapping,
   115→  same color story (green / amber / red on the dark substrate).
   116→- `src/components/sentinel/ai-visualizer/immersive-view.tsx` —
   117→  fullscreen overlay (ESC to close, `V` to toggle circuit/neural)
   118→  for wall-projection / SOC-monitoring use. Overlays scan progress,
   119→  live findings feed (from the SignalBus event ring), and AI status
   120→  prose per state.
   121→- `src/components/sentinel/ai-visualizer/index.ts` — barrel export
   122→  of the provider + hook + three views.
   123→- `src/components/sentinel/command-center.tsx` — wraps the dashboard
   124→  in `<SignalBusProvider>` and mounts `<ImmersiveView>` behind a
   125→  button, so every page that uses the command center gets a live
   126→  visualizer context.
   127→- `src/components/sentinel/landing/particle-bg.tsx` — `variant="circuit"`
   128→  swaps the homepage particle background for a dimmed (`opacity=0.35`,
   129→  HUD-off) `CircuitBoard` instance.
   130→

   191→## 2026-08-24 — warroom-voice-gesture: backtalk + barehands → War Room
   192→
   193→**Task ID:** `warroom-voice-gesture`
   194→**Scope:** Next.js web app at `/home/z/GuardianX-web`.
   195→
   196→Ported two of `@jaredrhod`'s open-source agent projects — `backtalk`
   197→(voice) and `barehands` (gesture) — into the GuardianX War Room as
   198→tri-modal (voice OR gesture OR mouse) input layers. Both reference
   199→repos are Python/HTML; this work reimplements their interaction
   200→vocabulary on pure browser APIs so they run inside the existing
   201→Next.js dashboard with no extra services.
   202→
   203→### What landed
   204→
   205→**Voice Control** (`src/components/sentinel/war-room/voice-control.tsx`)
   206→
   207→- backtalk shape (push-to-talk, status ring, spoken reply) on the
   208→  native Web Speech API. STT via `webkitSpeechRecognition` (Chrome/
   209→  Edge), TTS via `SpeechSynthesisUtterance` (cross-browser). **No
   210→  Python server, no API keys, no external deps.**
   211→- Push-to-talk: hold SPACE, or click the mic. 24-bar waveform
   212→  animation when listening. Status ring color: green (idle) / red
   213→  (listening) / amber (speaking).
   214→- Voice commands parsed locally by `parseVoiceCommand`:
   215→  `scan <codebase>`, `show <tab>`, `search findings for <query>`,
   216→  `approve patch <id>`, `what's the security posture?`, `stop`.
   217→- Imperative handle (`VoiceControlHandle`) exposes `speak` /
   218→  `stopSpeaking` / `startListening` / `stopListening` / `isSupported`
   219→  so the parent overlay can drive TTS from gesture or AI events.
   220→- Feature detection via `useSyncExternalStore` (no setState-in-effect,
   221→  no hydration mismatch). Stale-closure bug on the `onend` transcript
   222→  fixed with a `latestTranscriptRef` mirror so the React Compiler
   223→  preserves the `useCallback` memoization.
   224→
   225→**Gesture Control** (`src/components/sentinel/war-room/gesture-control.tsx`)
   226→
   227→- barehands vocabulary on `@mediapipe/hands` + `@mediapipe/camera_utils`
   228→  (npm packages, first-class TS types). WASM loaded from jsDelivr via
   229→  `locateFile`.
   230→- Gestures: **pinch** → synthetic click on element under cursor;
   231→  **swipe** (wrist x > 0.32 in < 380ms) → tab nav;
   232→  **open palm** → vertical scroll;
   233→  **fist** → synthetic ESC + `onGesture({kind:"fist"})`;
   234→  **two-hand pinch** → zoom (delta between two index tips).
   235→- Spring-animated fixed cursor tracks the index fingertip. Small
   236→  160×120 camera preview in the corner with hand-landmark skeleton
   237→  overlay (toggleable).
   238→- Graceful degradation: camera-permission / WebGL / model-load
   239→  failures show an "OFFLINE" chip; the rest of the War Room keeps
   240→  working with voice + mouse.
   241→
   242→**War Room Overlay** (`src/components/sentinel/war-room/war-room-overlay.tsx`)
   243→
   244→- Fullscreen (`fixed inset-0 z-[150]`) tri-modal overlay combining:
   245→  - `CircuitBoard` visualizer as a 55%-opacity background.
   246→  - Voice control card (toggle with `V`).
   247→  - Gesture control card (toggle with `G`).
   248→  - Tab strip: overview / clients / patches / findings / system
   249→    (cycleable with `← →`, voice "show <tab>", or gesture swipe).
   250→  - Live scan terminal (bottom-left, reads from `useSignalBus()`).
   251→  - KPI tiles, client pipeline cards, pending-patch list with inline
   252→    approve buttons, critical-findings feed with voice-driven filter,
   253→    system-status grid.
   254→- Closes on ESC, the Exit button, or a fist gesture (barehands'
   255→  "close modal" idiom).
   256→- Voice commands wired through `handleVoiceCommand`: `scan` looks up
   257→  the codebase by name (case-insensitive substring) and POSTs
   258→  `/api/scans`; `approve` POSTs `/api/patches/[id]/approve`; `search`
   259→  filters the in-memory findings list; `status` reads `/api/posture-
   260→  score` aloud; `navigate` switches the internal view + speaks the
   261→  label. Gesture `swipe` cycles views, `fist` closes the overlay.
   262→- Header shows live visualizer state, posture score, clock.
   263→
   264→**Voice Command API** (`src/app/api/voice-command/route.ts`)
   265→
   266→- POST, `requireAuth`-gated. Accepts pre-parsed command OR raw
   267→  transcript (mirrors `parseVoiceCommand` server-side so external
   268→  clients — mobile, CLI, agents — parse identically).
   269→- Handlers:
   270→  - `scan` → looks up codebase by name, prevents concurrent scans,
   271→    creates a `Scan` row, fire-and-forgets to the engine.
   272→  - `navigate` → no-op server-side (client handles view switch).
   273→  - `search` → ILIKE-style contains query on `Finding.title|category|
   274→    endpoint`, returns up to 25 matches.
   275→  - `approve` → resolves patch by `patchId` OR `id`, applies patched
   276→    source, appends to the tamper-evident attestation chain
   277→    (`computeAttestationHash`), fires `onPatchApproved` memory writer.
   278→  - `status` → computes posture score inline (same formula as
   279→    `/api/posture-score`), returns `{overall, grade, message}`.
   280→- Returns `{ok, action, message, ...payload}` per spec.
   281→
   282→**Command Center wiring** (`src/components/sentinel/command-center.tsx`)
   283→
   284→- Imported `WarRoomOverlay` and mounted it behind the existing
   285→  "War Room" button (`<WarRoomOverlay open={warRoom} onClose={...} />`).
   286→- The legacy `WarRoomMode` (auto-cycling 3-view fullscreen) is
   287→  replaced by a `_WarRoomModeLegacyStub` (no-op) so any external
   288→  imports still resolve; the War Room button now opens the tri-modal
   289→  overlay. The "Immersive View" button (circuit board only) is
   290→  unchanged.
   291→
